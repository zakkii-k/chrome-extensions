# Link Peekの読み込み速度

- ユーザーより、プレビューは動いたが読み込みが遅いとの報告と改善可否の質問。
- 0.1.1で実際のt.co→Yahoo記事を同じブラウザ内で3回開き、見出しまで447ms/845ms/709ms、短縮URLリクエスト152ms/121ms/135msを計測。別試行の初回は694ms・短縮URL138ms。ユーザー環境の速度を保証する値ではない。
- 改善対象は不要な再取得と直列処理。成功した短縮URL解決結果を実行中メモリに保持し、有効期限5分・最大64件・同時リクエスト共有・失敗は保存しない形にする。service workerの終了時は消える。
- 0.1.2で短縮URL解決とルール準備を並行化。ユーザー操作前の先読みや記事の広告・スクリプト除去は行わない。記事配信側の待ちは残る。

- 変更後の同じ条件の3回表示は493ms/600ms/560ms、短縮URLリクエストは初回151msの1回だけ。初回はネットワーク変動があり、全体時間の厳密な改善率とは扱わない。再表示時の約0.1秒台の余計な確認通信を削減できた。
- Node36件（新拡張16＋既存拡張20）と配布ZIP統合テスト4件を通過。新規プロファイルのChromiumで実記事の見出し表示を3回確認した。
