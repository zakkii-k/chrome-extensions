# リンクの一時プレビュー拡張

- ユーザーはX等でリンク先をページ上のモーダルとして開き、領域外クリックで閉じる機能を希望。拡大ボタンを押したときだけ通常の新規タブにする。Arcの参考画像を添付。
- 参考機能はArcのPeek。OSの別ウィンドウを出す要望ではない。
- 開くトリガー（全サイトの外部リンクの通常クリック／Shiftクリックのみ／Xの外部リンクだけ通常クリック）について確認中。
- 既存の検索ランチャーとは別の拡張として同じリポジトリ内で管理する構成が適している。
- 実装調査ではiframeによるリンク先表示がサイト側の埋め込み制限（X-Frame-Options、CSP frame-ancestors等）の影響を受けることを確認。Arc本体と同等の全サイト対応を約束しない。参考画像のYahooニュースも実際の表示可否の確認が必要。
- 全サイトの外部リンクを通常クリックで開く仕様をユーザーが選択。feat/link-peekブランチにLink Peek 0.1.0として追加。
- 元のページにHTML dialogを重ね、独立した拡張機能フレーム内でリンク先をiframe表示する。閉じる・拡大以外の常時説明文は置かない。元のページとタブ数を維持し、拡大操作時だけ現在表示中のURLを新規タブで開く。
- Yahooニュースの公開レスポンスがX-Frame-Options: DENYであることを確認。対応として、表示元タブID＋拡張機能が開始元のサブフレームに限定したセッションルールでX-Frame-Optionsだけ除外。CSPやCookieには触れない。閉じる・元ページ移動・タブ終了時にルールとプレビュー情報を削除。
- サイトのCSP frame-ancestorsで拒否された場合はプレビュー不可表示にし、明示操作でタブを開く。自動で別タブやOSウィンドウを作らない。
- iframe内リンクの遷移を拡張フレーム経由で行い、リダイレクトと現在URLを追跡。Escは記事内にフォーカスがある場合にも対応。内部リンク・修飾キー・中央クリック・ダウンロードは原則元の動作を維持。有効／無効は拡張機能アイコンで切り替え可能。
- frontend-testing-debuggingスキルの手順を使用。Browser plugin not availableのため既存Playwright/Chromiumを使用。製品の閉じたShadow DOMは変更せずCDPでボタン位置を取得して実際のクリックを行った。
- ローカルの2オリジンのHTTPテストサイトで、通常クリック時にタブが増えないこと、領域外クリック、記事内Esc、プレビュー内遷移後の拡大URL、リダイレクト、X-Frame-Optionsの限定例外と閉じた後の削除、CSPを維持した拒否表示、元ページの厳しいframe-src、内部リンク維持を確認。実行時ページエラーなし、閉じた後のsession情報と例外ルールは空。
- 1280x800と390x844の表示を確認。Yahooニュースの実ページもデスクトップ幅でプレビューできることを確認。スクリーンショットは/tmpに保存。実際のログイン済みX・Diaでは未検証。
- Node自動テストは新拡張7件＋既存拡張20件、配布ZIP統合テスト4件を通過。Python標準ライブラリのパッケージ生成で本体ZIPとWindows用ZIPを生成。
- Windows PowerShellでprepare.ps1を実行し、C:/Users/zakki/AppData/Local/LinkPeek/extensionに配置した。ブラウザへの新規読み込みと既存ページの再読み込みはユーザー操作が必要。
- 検索ランチャーや既存公開リリースは変更していない。新しい拡張のストア公開は行っていない。
